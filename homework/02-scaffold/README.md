# Задание 2. Скафолд: сервер, сетка, токены, ритм и первый лендинг

**Что получится:** маленькая собственная дизайн-система в коде и простой лендинг, который агент
собрал по вашим правилам. Цвет, шрифт, сетка и отступы заданы не «на глаз» в каждом месте, а
**параметрами в одном файле**. Поменяли параметр — поменялась вся страница, и она остаётся
цельной.

**Главная мысль задания.** Агент по умолчанию делает усреднённо: берёт готовую дизайн-систему
или случайные значения. Чтобы он делал по-вашему, ему нужно не «сделай красиво», а
**правила**: из чего выводится каждый цвет, какие отступы вообще существуют, к каким колонкам
привязан блок. Сегодня вы пишете эти правила в первый раз.

**Время:** 2–3 сессии с агентом.

**Нужно:** выполненное задание 1 (Claude Code, GitHub, рабочий цикл сессий).

## Шаг 1. Локальный веб-сервер

Страницу можно открыть и двойным кликом по файлу, но так работает не всё. Нужен маленький
веб-сервер у вас на компьютере: он показывает страницу по адресу вида
`http://localhost:3000` и сам обновляет её в браузере, как только агент что-то поменял. Это
главный инструмент петли «агент правит → вы смотрите».

Серверу нужна программа **Node.js**. Скажите агенту:

> Подними локальный веб-сервер с автообновлением страницы (browser-sync через npm run dev).
> Если Node.js не установлен — сначала скажи, что и как поставишь, и дождись моего «да».

Если агент попросит поставить Node.js вручную:

- **macOS:** скачайте установщик LTS с https://nodejs.org и прощёлкайте.
- **Windows:** в терминале `winget install OpenJS.NodeJS.LTS`, затем закройте и откройте
  терминал заново.

**Готово, когда:** вы вводите `npm run dev`, открывается браузер со страницей, а правка
файла агентом сама появляется в браузере без перезагрузки руками.

Сервер работает, пока открыт терминал, в котором он запущен. Для разговора с агентом держите
второе окно терминала, либо попросите агента запускать сервер в фоне.

## Шаг 2. Параметры — ваш дизайн одним файлом

Создайте с агентом файл `design-params.md` и заполните его **сами**. Это главное решение
задания: агент предлагает варианты и объясняет последствия, но выбираете вы. Шаблон ниже,
значения в нём — пример, а не рекомендация.

```markdown
# Параметры дизайна

## Цвет — всё из одного тона (HSL)
- hue (тон, 0–360): 150
- тема: тёмная
- насыщенность нейтральных: 10%
- лестница светлоты нейтральных:
  - фон: 15%
  - поверхность (карточки): 20%
  - приглушённый текст: 35%   ← подписи, второстепенное
  - основной текст: 80%
  - заголовки: 95%
- акцент: тон hue + 180 (противоположный на круге), насыщенность 100%, светлота 50%

## Шрифт
- гарнитура: Golos Text (Google Fonts, файлы скачать в проект)
- базовый кегль: 18px (мобайл 16px)
- шкала кеглей: база × 1.25 на каждую ступень вверх (18 → 22.5 → 28 → 35 → 44)
- межстрочный: 1.55 для текста, 1.15 для крупных заголовков
- начертания: 400 текст, 600 заголовки

## Сетка
- колонок: 12 на десктопе, 4 на мобайле (граница 768px)
- гаттер (зазор между колонками): 24px, мобайл 12px
- поля по краям: 32px, мобайл 16px
- максимальная ширина контента: 1200px

## Вертикальный ритм — шкала отступов
- ступени (десктоп): 8 / 16 / 32 / 64 / 128
- планшет: × 0.75, мобайл: × 0.6
- роли ступеней:
  - 8 — внутри одной мысли (заголовок и его подзаголовок)
  - 16 — строки одной группы (пункты списка)
  - 32 — соседние элементы блока (текст и картинка к нему)
  - 64 — между блоками
  - 128 — между крупными разделами страницы
```

### Почему цвет задан так, а не списком hex-кодов

Посмотрите на лестницу светлоты: все нейтральные цвета — это **один и тот же тон** с разной
светлотой. Акцент выведен **правилом** (противоположный тон), а не подобран отдельно. Поменяйте
hue со 150 на 20, и вся палитра переедет в тёплые тона, сохранив все отношения между цветами:
текст так же читается на фоне, приглушённое так же отступает назад, акцент так же спорит с
фоном. Это и есть формализация: вы описали не цвета, а **отношения между ними**.

Так устроен живой пример — читалка заметок, у которой при каждой загрузке случайный hue, а
палитра всегда цельная:

```css
:root {
  --hue: 150;
  --bg:      hsl(var(--hue) 10% 15%);
  --text:    hsl(var(--hue) 10% 80%);
  --muted:   hsl(var(--hue) 10% 35%);
  --muted-2: hsl(var(--hue) 10% 20%);
  --accent:  hsl(calc(var(--hue) + 180) 100% 50%);
}
```

Честная оговорка: светлота в HSL не совпадает с тем, как светлоту видит глаз. Жёлтый при 50%
выглядит гораздо светлее синего при тех же 50%. Поэтому после выбора hue **попросите агента
проверить контраст текста к фону** по стандарту доступности (WCAG: не ниже 4.5:1 для обычного
текста). Не проходит — двигайте светлоту на лестнице, а не цвет в одном месте. Точнее эту
проблему решает модель OKLCH, к ней вернёмся позже в курсе.

### Почему отступы — шкала, а не значения

Отступ — это не «сколько места оставить», а **сообщение о родстве**: насколько элементы
связаны по смыслу. Это закон близости из гештальт-психологии: близкое глаз читает как одну
группу. Правило шкалы: **чем дальше смысловое родство двух блоков, тем выше ступень между
ними.** Заголовок и подзаголовок — одна мысль, ставим 8. Два раздела лендинга — разные мысли,
ставим 128.

Ступеней мало намеренно. Если на странице может стоять любое число пикселей, отступы
перестают что-либо сообщать. Если их пять, каждая ступень — слово в языке страницы.

## Шаг 3. Токены

Попросите агента:

> По design-params.md собери файл styles/tokens.css: все цвета, кегли, шкалу отступов и
> параметры сетки как CSS-переменные. Цвета — формулами hsl() от --hue, как в примере из
> задания. Мобильные значения переключаются внутри токенов через @media, чтобы остальной CSS
> писал var(--space-64) и не думал о размере экрана. Покажи мне таблицу: имя токена →
> значение → откуда взялось в design-params.md.

**Токен** — это именованный параметр дизайна, например `--space-64` или `--color-muted`.
Остальной CSS обращается к дизайну только через токены.

**Правило, которое агент должен соблюдать дальше:** в стилях страницы нет ни одного «голого»
значения цвета, кегля или отступа. Только `var(--…)`. Нужного значения нет в токенах —
значит, либо подходит соседняя ступень, либо это новое решение, и оно сначала записывается в
`design-params.md`.

Ловушка, о которой полезно знать: если в `var(--space-60)` опечататься и такого токена нет,
браузер не покажет ошибку. Свойство просто молча обнулится, и отступ пропадёт. Когда что-то
«исчезло», первым делом проверьте имя токена.

## Шаг 4. Сетка и её оверлей

> Сделай сетку страницы по design-params.md на CSS Grid. И дев-инструмент: по клавише G
> поверх страницы появляются полупрозрачные колонки сетки, поля и гаттеры, повторное
> нажатие — убирает. Инструмент подключается отдельным файлом, чтобы его легко было убрать
> перед публикацией.

С оверлеем вы видите, стоит ли блок в колонках, или агент поставил его «примерно».

**Главное правило раскладки — две ручки на блок.** В стилях каждый блок страницы объявляет
ровно две вещи:

1. **привязку к колонкам** — `grid-column: 1 / 7` (с какой по какую колонку);
2. **отбивку** — `margin-bottom: var(--space-64)` (ступень шкалы до следующего блока).

Больше ничего про положение. Тогда композицию можно менять правкой одной строки: «сдвинь
текст на колонки 3–9», «между этими блоками 128 вместо 64». Такие просьбы агент выполняет
точно, потому что они сформулированы на языке системы.

## Шаг 5. Лендинг

Придумайте простой лендинг на любую тему: свой проект, выдуманный продукт, мероприятие.
Состав:

1. **Первый экран:** заголовок, одна фраза пояснения, кнопка.
2. **Три преимущества** в ряд на десктопе, столбиком на мобайле.
3. **Крупная картинка** на всю ширину сетки (подойдёт любая своя).
4. **Цитата или отзыв** — узкий блок, не на всю ширину.
5. **Призыв и подвал:** повтор кнопки, контакты.

Опишите агенту **композицию словами системы**, а не пикселями. Например: «заголовок первого
экрана — колонки 1–8, пояснение под ним через ступень 16, кнопка через 32. Преимущества — три
равные группы по 4 колонки, внутри группы заголовок и текст через 8. От первого экрана до
преимуществ — 128».

Обязательно для интерактивных элементов (кнопки, ссылки):

- **состояние наведения** — только внутри `@media (hover: hover)`, иначе на телефоне оно
  «залипает» после тапа;
- **состояние фокуса с клавиатуры** (`:focus-visible`) — видимое, вне этого медиа-запроса.

Интерфейс — это не картинка, а набор состояний. Агент их пропускает, если в правилах их нет.

## Шаг 6. Петля проверки — самое важное

Сейчас у вас есть страница. Дальше начинается основной навык курса:

1. **Скриншот.** Попросите агента снять страницу на двух ширинах: 1440px и 390px.
2. **Разбор.** Смотрите сами, с включённой сеткой (G). Что не так? Сформулируйте на языке
   системы: «блок цитаты не привязан к колонкам», «между заголовком и текстом 32, а по
   правилу родства должно быть 8», «приглушённый текст не читается».
3. **Правка в правилах, а не в месте.** Если проблема общая, правится `design-params.md` →
   токены, а не один блок. Если частная — правится одна из двух ручек блока.
4. **Перегенерация и новый скриншот.**

Запретные формулировки: «сделай покрасивее», «подвигай немного», «что-то не то». Каждая
такая просьба заставляет агента угадывать, и он угадает усреднённо.

**Два обязательных опыта:**

- Поменяйте только `hue` в параметрах. Вся страница должна перекраситься цельно, без ручных
  правок. Если где-то остался старый цвет — это найденное голое значение, почините его.
- Поменяйте одну ступень шкалы (например 64 → 80). Изменились все межблочные отступы разом —
  значит, система работает.

## Шаг 7 (по желанию). Figma MCP — агент читает ваши макеты

**MCP** — способ подключить агенту внешний инструмент. Figma MCP даёт Claude Code доступ к
вашим файлам в Figma.

Подключение (один раз, в обычном терминале):

```
claude mcp add --transport http figma https://mcp.figma.com/mcp
```

Затем в сессии Claude Code введите `/mcp`, выберите `figma` → Authenticate и войдите в
Figma в браузере.

Что агент сможет:

- **прочитать фрейм по ссылке** (правый клик по фрейму → Copy link to selection) — структуру,
  размеры, тексты, цвета;
- **достать переменные** (Variables) файла — готовый материал для токенов;
- **сделать скриншот фрейма**, чтобы сравнить макет с тем, что получилось в браузере;
- в новых версиях — **рисовать в Figma**: собрать страницу из кода обратно в макет.

Ограничения: на бесплатных тарифах Figma число обращений заметно ограничено, актуальные
лимиты смотрите в справке Figma. Для работы через десктопное приложение (без облака) есть
отдельный локальный вариант подключения, его описывает справка Figma по Dev Mode MCP.

**Упражнение для этого курса.** Возьмите чужой лендинг, который вам нравится (скриншот в Figma
или макет из Community). Попросите агента **не сверстать его, а разобрать**:

> Разбери этот фрейм в формат моего design-params.md: какой тон и лестница светлоты, какая
> шкала кеглей, сколько колонок, какие ступени отступов. Где значения не ложатся в систему —
> не подгоняй молча, покажи мне список расхождений.

Одиночное отклонение от системы у автора чужого макета — скорее всего случайность, её можно
округлить до ближайшей ступени. А повторяющееся — вероятно, правило, которое вы ещё не
заметили. Это и есть декомпозиция, с которой начнётся следующий модуль.
